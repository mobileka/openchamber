# Scheduled Tasks

A scheduled task runs a prompt for you on a schedule — for example, a check every 30 minutes or a daily digest. When it runs, OpenChamber starts a new session and sends the prompt on its own. Open the scheduler from the button at the top of the session sidebar.

Every task is a **loop**: a portable markdown file you can commit. There are no project-scoped tasks — loops live in two fixed places:

- **Shared** — `$OPENCODE_CONFIG_DIR/.agents/loops/*.md`, synced via git. Shared loops run on every machine.
- **Local** — `~/.agents/loops/*.md`, this machine only.

If a local and a shared loop share a file name, the local one wins.

## Create a task

1. Open the scheduled tasks dialog from the session sidebar.
2. Press **New task** and pick **Local** or **Shared**. The location is fixed afterwards — it decides which directory the file is written to.
3. Give it a name (becomes the `<name>.md` file), a cron expression for when it runs, the provider, model, and agent to use, and optionally a working directory (defaults to the synced repo root). The prompt can be a slash command, like `/review`.
4. Save, and make sure the task is enabled.

You can run any task immediately with **run now** to check it does what you expect.

## Loop file format

The task name is the file name without `.md`:

```markdown
---
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
directory: ~/dev/opencode
---
Summarize repository changes since yesterday and post the digest.
```

### Fields

| Field | Meaning |
|---|---|
| `schedule` | Cron expression (required) — loop files are cron-only. |
| `enabled` | Set `true` to run. Loops are **off by default**, so committing a file never starts running a task on its own. |
| `model` | `provider/model` (required), e.g. `anthropic/claude-sonnet-4-5`. |
| `agent` | Agent to use (optional). |
| `timezone` | IANA timezone (optional, defaults to the server zone). |
| `directory` | Working directory for runs (optional, `~` allowed, defaults to the synced repo root). |
| body | The execution prompt (required). Can be a slash command, like `/review src/`. |

### How loops behave

- The **file is authoritative** while it exists. **Edit** opens it in the built-in file editor, the enabled toggle updates its frontmatter, and deleting the task deletes the markdown file after confirmation. **Run now** remains available.
- Runtime state (last run, next run, status) lives in the machine-local `$OPENCHAMBER_DATA_DIR/scheduled-tasks.json` and is never written back into the markdown file — or synced.
- Renaming the file renames the task (run history starts fresh). Editing anything else keeps the task and its state in place. If a loop file temporarily fails to parse (mid-edit, merge conflict), its task is kept with the last good definition until the file is fixed.

## What success looks like

After a run, the task shows when it last ran, whether it succeeded, and a link to the session it created. If a run fails, the error is shown there too.

## Keep in mind

Tasks only fire while the OpenChamber server is running. If you close it, scheduled runs are paused until it's back up.
